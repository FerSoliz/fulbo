# Documentacion de la Plataforma

Este directorio centraliza toda la documentacion del proyecto.

Primera lectura recomendada: `documentacion/00-contexto-inicial.md`.

## Estructura

- `documentacion/00-contexto-inicial.md`: entrada unica de contexto y orden de lectura.
- `documentacion/producto/plataforma.md`: vision funcional, modulos, roles y flujos clave.
- `documentacion/producto/guia-usuario.md`: guia funcional para usuarios finales.
- `documentacion/arquitectura/blueprint.md`: arquitectura tecnica actual (Realtime-only).
- `documentacion/dev/convenciones.md`: reglas de trabajo, calidad y mantenimiento.
- `documentacion/dev/directrices-reconstruccion.md`: directrices formales para reconstruccion del proyecto.
- `documentacion/dev/ai-contexto-inicial.md`: contexto inicial para IA y mapa de fuentes de verdad.
- `documentacion/dev/entornos-y-secretos.md`: estandar de entornos y manejo de secretos.
- `documentacion/dev/prompt-system.md`: definicion y versionado del sistema de prompts.
- `documentacion/checklists/implementacion-checklist-1.md`: checklist operativo ejecutado y estado de cierre.
- `documentacion/checklists/pre-etapa-2-checklist.md`: checklist de cierre previo al inicio formal de etapa 2.
- `documentacion/checklists/qa-pre-etapa-2-ejecucion.md`: ejecucion de QA tecnico y matriz funcional previa a etapa 2.
- `documentacion/checklists/registro-tareas.md`: bitacora obligatoria de tareas implementadas.
- `documentacion/plantillas/plantilla-documento.md`: plantilla base para nuevas docs.
- `documentacion/plantillas/plantilla-registro-tarea.md`: plantilla obligatoria para registrar tareas.

## Regla de orden

- Todo documento nuevo se crea dentro de `documentacion/`.
- No crear docs sueltos en la raiz.
- Usar nombres en `kebab-case` para archivos nuevos.
- Si un doc cambia de lugar, actualizar este indice y el `README.md` de raiz.
